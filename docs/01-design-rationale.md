# 01. 설계 근거 — 학습 문제, 이론, LDT × AIEDAP, 결정 기록

## 1. 한 줄 요약
보존과학자의 실제 사례 5개를 '선택-결과 그래프'로 겪게 하고, 사례들에서 공통 알고리즘을 귀납해 내게 하여, **"보존은 새것처럼 고치는 일이 아니라 증거에 따라 되돌릴 수 있게 판단하는 일"**임을 발견하게 한다.

## 2. 학습 문제 (LDT: Learning Problem)
스탠퍼드 LDT 석사 프로젝트는 학습 문제를 파악하고, 학습과학에 근거한 해결책을 만들어 시험하고, 학습의 증거를 모을 것을 요구한다. 이 수업의 학습 문제는 아래 **가설**이다(수업 전·중에 확인한다).

| # | 가설(학습 문제) | 확인 방법 |
|---|---|---|
| H1 | 초등 고학년은 보존을 '새것처럼 고치기'로 오해한다 | 도입: "보존과학자는 무엇을 할까?" 한 줄 쓰기(학습지 W1 뒷면) |
| H2 | 영재 학생도 근거보다 '정답 맞히기'를 서두른다 | 사건마다 근거 태그 입력 비율(로그) |
| H3 | AI의 답을 근거 확인 없이 받아들이기 쉽다 | AI 점검 화면에서 체크리스트 적용 전후 판단 변화 |
| H4 | 사례를 하나씩 배우면 공통 원리로 일반화하지 못한다 | 알고리즘 도출 화면의 학생 발화 + 전이 학습지 W3 |

## 3. 학습자
- 대상: 초등 5학년 영재학급 16명 → 직소 4×4(전문가 4분야 × 본 팀 4개).
- 예상 강점: 규칙 찾기, 추론, 게임 몰입. 예상 어려움: 근거를 말로 설명하기, 성급한 결론, 협업 중 역할 쏠림.
- 사전 확인할 것: 학생 기기 유무, 실과 알고리즘(순서도) 학습 여부, 문화유산 관련 선수 학습.

## 4. 학습 목표 (AIEDAP 3영역 형식)
| 영역 | 목표 |
|---|---|
| 지식·이해 | 문화유산이 손상되는 원인(물리·화학·생물·사람)과 보존과학의 원칙 5가지를 사례와 연결해 설명한다. |
| 과정·기능 | 가상 실습에서 예측하고 관찰한 증거로 선택하며, 여러 사례의 선택을 비교해 공통 알고리즘을 귀납하고 새 사례에 적용한다. 규칙 기반 판단(알고리즘)과 생성형 AI의 판단을 비교·점검한다. |
| 가치·태도 | 빠른 방법과 되돌릴 수 있는 방법, 기한과 정직이 부딪힐 때 근거와 원칙으로 판단하고, 과거 보존 결정을 그 시대의 지식으로 공정하게 평가한다. |

### 보존과학자의 원칙 5가지 (= 알고리즘의 단계)
| ID | 단계 키 | 원칙 | 초5 문장 |
|---|---|---|---|
| P1 | investigate | 먼저 조사하고 기록한다 | 손대기 전에 살펴보고, 있는 그대로 적어요. |
| P2 | rootCause | 겉이 아니라 원인을 고친다 | 보이는 것 말고, 왜 그렇게 됐는지를 찾아요. |
| P3 | reversible | 되돌릴 수 있는 방법을 쓴다 | 나중 사람이 다시 고칠 수 있게 해요. |
| P4 | minimal | 필요한 만큼만 고친다 | 원래 것을 최대한 남겨요. |
| P5 | evidence | 증거가 없는 것은 만들지 않는다 | 상상으로 채우지 않아요. |

## 5. 학습 이론 → 설계 기능 (LDT 기준 ③)
이론은 **두 개로 제한**한다. 모든 기능은 둘 중 하나로 설명되어야 한다.

| 이론 | 핵심 | 이 이론이 만든 기능 |
|---|---|---|
| A. 경험 기반 시뮬레이션 + 예측-관찰-설명(POE) + 즉각 피드백 | 결과를 보기 전에 예측하게 하고, 선택의 결과를 즉시·지연해서 보여주면 오개념이 드러나고 수정된다 | 예측 화면, 가상 실습, ✓/△/✕ 결과, '시간 빨리 감기'(지연 결과), '다른 길 보기', 실제 역사 공개 |
| B. 직소 협동학습(긍정적 상호의존 + 개별 책무성) | 정보가 흩어져 있어 서로의 지식 없이는 풀 수 없게 만들면 모두가 기여한다 | 전문가 매뉴얼 4종(서로 다른 정보), 전문가 미니 퀴즈, 사건마다 '필요한 전문가' 호출, 주도 전문가 설명 후 투표 |

설계 원리(이론이 아니라 학습 목표를 위한 장치): **사례 → 알고리즘 귀납**. 다섯 사건의 결정마다 원칙 단계 태그를 붙이고, 마지막에 '알고리즘 매트릭스'로 겹쳐 보여준다(docs/05 §6).

## 6. 사고 흐름 — 「사각형 범인 체포 앱」에서 일반화
교사가 공유한 AIEDAP 지도안의 사고 흐름을 추상화해 보존과학 업무로 치환했다.

| 사고 단계 | 사각형 수업 | 보존과학자 업무 | 웹앱 구성요소 |
|---|---|---|---|
| ① 단서 | 평행·변·각 | 녹의 색, X선, 성분, 실습 측정값 | 사건 브리핑, 가상 실습 |
| ② 규칙 | 판독표 | 전문가 매뉴얼(단서 → 원인 → 처리) | manual 모드, 주도 전문가 설명 |
| ③ 외재화 | 판독표 → 앱 | 팀 판단 기록(예측·선택·근거 태그) | 팀 선택 입력, 학습지 W2 |
| ④ 반증 | 가짜 목격담 | 예측이 틀린 실습, 지연 결과, 실제 역사와 다른 선택 | POE, 시간 빨리 감기, 역사 공개 |
| ⑤ 규칙 vs 생성형 AI | 체포 앱 vs 제미나이 | 우리 알고리즘으로 AI 답변 점검 | AI 조수 점검 화면 |
| ⑤+ 규칙 너머의 판단 | (없음) | 몇 층까지 복원할까(증거와 가치) | 사건 5 토의형 결정 |
| ⑥ 전이 | 현상수배지 | 내가 고른 문화유산 보존 계획 | 전이 화면, 학습지 W3 |

## 8. AIEDAP 정합성
### 8.1 지도안 양식(교사 제공 자료 5편 기준)
정교화(학습자 분석 체크 / 학습 환경 분석 / 평가·학습 주제 8문항 / 성취기준·학습자 특성 → 분석 결과) → 지도안(수업 목표 3칸: 성취기준 / 인공지능 관련 내용 / 교과+AI융합, 상·중·하 평가 계획, 차시별 도입-전개-마무리 + 활용 AI·디지털 도구). 초안은 docs/02 §5.

### 8.2 수업 유형 판단
- 교사 제공 5편은 모두 '수업 유형: AI 프로그램 개발'이며, 다섯 편 모두 **학생이 프로그램을 만들거나 고친다**.
- 이 수업은 교사가 만든 웹앱을 쓰므로 그 정의와 다르다. 권장: **AI 내용요소 연계형**(AIEDAP 실천유형 2: 알고리즘·문제 해결 절차 연계).
  - AI 관련 내용: 규칙 기반 판단(선택 그래프 = 알고리즘)과 생성형 AI 판단 비교, 그래프에서 길 찾기(탐색), 측정 데이터에 근거한 판단, 실제 보존 현장의 AI 활용(국립중앙박물관 보존과학센터의 AI 기반 손상도 측정 추진).
- 'AI 프로그램 개발'로 쓰려면 전이 활동에서 학생이 자기 문화유산의 선택 그래프(조건 분기 알고리즘)를 **설계하고 친구 팀이 검증**하는 부분을 근거로 든다.

### 8.3 AIEDAP 평가·학습 주제 8문항 자기 점검
| 문항 | 충족 근거 |
|---|---|
| 1. AI/디지털과 명확히 연결 | 선택 그래프(알고리즘), AI 답변 점검, 데이터 기반 실습 |
| 2. AI/디지털 활용의 당위성 | 수십~수백 년 걸리는 결과(녹, 접착제 변색, 콘크리트 부식)를 시뮬레이션으로만 2시간 안에 겪을 수 있음 |
| 3. 실생활·사회적 맥락 | 실제 사건 5개 + 2023년 경복궁 담장 낙서 |
| 4. 적용 방안의 구체성 | docs/04 화면 명세, docs/06 실습 명세 |
| 5. AI/디지털로 과제 수행 | 가상 실습 측정, 알고리즘 매트릭스, AI 점검 체크리스트 |
| 6. 역량 함양 | 증거 기반 판단, 일반화, 비판적 AI 사용, 협업 |
| 7. 성취기준 분석 적합 | 실과 [6실05-01] 알고리즘 표현 + 사회·과학 연계(교사 확정) |
| 8. 학습내용 분석 적합 | 원칙 5가지 ↔ 사건 결정 태그 1:1 대응(docs/05 §6) |
