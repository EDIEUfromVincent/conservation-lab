# 04. 화면 명세

모든 화면은 1920×1080 무대 기준. 학생 화면 문구는 `data/scenario.json`에서 읽는다. 공통 요소:
- 상단 바: 현재 단계 이름, 사건 번호(●●○○○), 남은 시간 칩, 팀별 건강도 미니 막대 4개.
- 오른쪽 아래: 다음(→) 안내. 교사 패널(T)은 오른쪽에서 밀려 나온다.

---

## S00 시작·설정 (교사만)
```
┌──────────────────────────────────────────────────────────┐
│  보존과학자의 하루                                         │
│  [프로필]  ◉ 120분 연속   ○ 80분(2차시)                   │
│  [팀 이름] 1팀 [____] 2팀 [____] 3팀 [____] 4팀 [____]     │
│  [옵션]   ☑ 선택적 결정 포함  ☐ 실습 빠른 모드             │
│  [AI 답변] 캡처됨 ✓ / 없음 ⚠ (교사 패널에서 붙여넣기)       │
│  [영상]   링크 확인 ✓                                     │
│  저장된 수업이 있습니다 →  [이어하기] [새로 시작]           │
│                                     [수업 시작 →]          │
└──────────────────────────────────────────────────────────┘
```
- 프로필을 바꾸면 `skipOptional`, `quickLabs` 기본값이 프로필 값으로 바뀐다.
- 콘텐츠 검증 결과(오류·경고)를 여기서 보여준다.

## S01 오늘의 미션
- 큰 제목 + 한 줄 미션: "오늘 여러분은 문화유산을 지키는 보존과학자입니다."
- 발문 카드: "'문화재'와 '국가유산', 무엇이 다를까?" (`intro.question`)
- 학생은 W1 뒷면에 "보존과학자는 무엇을 할까?" 한 줄 쓰기.

## S02 영상
- 영상 제목·길이·출처 + [새 탭에서 열기] 버튼(`video.url`). 로컬 파일 경로가 있으면 `<video>`로 재생(`video.localFile`).
- 시청 포인트 3개를 화면에 미리 띄움(`video.watchFor`).

## S03 지키고 싶은 문화유산
- 안내 문구 + 예시 카드 6장(전국 고루, 일러스트) + 타이머.
- 학생은 W1 앞면에 작성. 앱은 입력을 받지 않는다(개인정보·시간 절약).

## S04 전문가 모임
```
┌──────────────────────────────────────────────────────────┐
│  전문가 모임  ⏱ 10:00                                     │
│  ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐                  │
│  │ ● 금속 │ │ ▲ 유리 │ │ ■ 페인트│ │ ◆ 접착 │                  │
│  │ [QR]  │ │ [QR]  │ │ [QR]  │ │ [QR]  │                  │
│  └───────┘ └───────┘ └───────┘ └───────┘                  │
│  할 일: ① 매뉴얼 읽기 ② 퀴즈 3문항 ③ 본 팀에 설명할 3문장 준비 │
│  [통과한 모임 체크]  금속 ☐  유리 ☐  페인트 ☐  접착 ☐         │
└──────────────────────────────────────────────────────────┘
```
- QR은 같은 파일 경로 + `?mode=manual&expert=…`. 파일 경로는 S00에서 교사가 입력(예: 교내 공유 주소). 비어 있으면 QR 대신 "인쇄 매뉴얼을 나눠 주세요" 표시.

## S05 본 팀 구성
- 팀 4개 카드, 각 카드에 네 분야 배지 자리. 교사가 클릭해 확인 표시(이름 입력 없음).
- 역할 규칙 안내: 주도 전문가 = 설명·발표, 보조 = 보충, 나머지 = 기록자·질문자.

## S06 연습 사건
- `tutorial` 데이터로 S10~S19의 축소판을 한 번 돌린다(실습 없음). 투표 입력·근거 태그·결과 공개 조작을 익히는 용도. 점수에 반영하지 않는다.

```
┌──────────────────────────────────────────────────────────┐
│ 사건 1 · 1980년 · 미국 뉴욕                 ●○○○○  ⏱1:30 │
│ ┌──────────────┐  자유의 여신상의 녹                        │
│ │  일러스트     │  · 1980년, 미국 뉴욕 항구의 자유의 여신상.   │
│ │  (사건 장면)  │  · 겉은 초록색으로 덮여 있어요.              │
│ │              │  · 몸속 철 뼈대가 부풀고 녹슬고 있어요.       │
│ └──────────────┘  · 무엇부터 해야 할까요?                    │
```

- `brief.lines`를 한 줄씩 등장(→ 키). 최대 5줄.

## S11 전문가 호출
- 큰 배지로 "이번 사건에 필요한 전문가: 주도 ● 금속 / 보조 ◆ 접착 · ■ 페인트".
- 안내: "주도 전문가는 매뉴얼의 관련 내용을 팀에 2분 동안 설명하세요." 타이머.
- 교사 패널: 해당 매뉴얼의 핵심 문장(`manuals.json` → `callouts[caseId]`).

## S12 예측 (POE의 P)
```
┌──────────────────────────────────────────────────────────┐
│ 예측: 3일 뒤 어느 못이 가장 많이 녹슬까요? 순서를 정하세요.  │
│  ┌ 쇠못만 ┐  ┌ 쇠못+구리선 ┐  ┌ 쇠못|테이프|구리선 ┐         │
│  1팀 [1][2][3]   2팀 [ ][ ][ ]   3팀 …   4팀 …              │
│                                    [예측 잠그기 Enter]     │
└──────────────────────────────────────────────────────────┘
```
- 예측 형식: `rank`(순서), `choice`(하나 고르기), `number`(숫자 예상). 팀별로 입력, 잠그면 수정 불가.
- 예측은 실습 뒤 결과와 나란히 비교된다(S13 마지막).

## S13 가상 실습 (POE의 O)
- 실습별 화면은 docs/06. 공통 틀:
```
┌──────────────────────────────────────────────────────────┐
│ 실습 1 · 두 금속이 맞닿으면?              [빠른 모드] ⏱3:00 │
│ ┌──────────────────────────────┐ ┌──────────────────────┐ │
│ │        실습 캔버스            │ │ 측정·기록 패널        │ │
│ │                              │ │ (결과 표/그래프)      │ │
│ └──────────────────────────────┘ └──────────────────────┘ │
│ [실물 사진 보기] (assets/pilot 있을 때)                    │
│ 예측 vs 결과: 1팀 ✓  2팀 ✗  3팀 ✓  4팀 ✗                   │
└──────────────────────────────────────────────────────────┘
```
- 실습이 끝나면 측정값을 `labResults`에 저장하고 로그에 남긴다.
- 예측이 틀린 팀을 강조하지 않는다. 대신 교사 패널에 "예측이 틀린 팀에 이유 묻기" 발문.

## S14 팀 선택 입력 (결정 노드)
```
┌──────────────────────────────────────────────────────────┐
│ 결정: 몸속 철 뼈대를 어떻게 할까요?            ⏱1:30       │
│ 상황: 철 뼈대는 구리 겉면과 맞닿아 있어요. …                 │
│  (A) ○ 같은 철로 새 뼈대를 만든다                          │
│  (B) △ 녹슬지 않는 금속으로 바꾸고 구리와 사이에 막을 끼운다  │
│  (C) □ 철 뼈대에 검은 페인트만 덧칠한다                      │
│ 팀 선택:  1팀 [B]  2팀 [B]  3팀 [A]  4팀 [ ]                 │
│ 근거 태그: [실습 결과] [매뉴얼] [원칙 P1~P5]                │
│                                   [결정 확정 Enter]         │
└──────────────────────────────────────────────────────────┘
```
- 팀들은 A/B/C 카드를 **동시에** 든다(교사 "하나, 둘, 셋!"). 교사가 1~4 + A~C 키로 입력.
- 근거 태그는 선택 입력(빠르게: `lab`, `manual`, `P1`~`P5`).
- 반 경로 = 다수결. 동점이면 교사가 근거 발표를 듣고 고른다(로그 `decidedBy: "teacher"`).
- 선택지 앞 기호(○△□)는 카드 모양과 같다. 결과 기호(✓△✕)와 헷갈리지 않도록 결과 화면에서만 ✓△✕를 쓴다.

## S15 결과 공개
```
┌──────────────────────────────────────────────────────────┐
│ 반의 선택: (B)                                            │
│ ✓ 해결 — 두 금속이 직접 닿지 않으니 '금속끼리 생기는 녹'이 멈춰요. │
│ 원칙 카드 획득: P2 겉이 아니라 원인을 고친다                 │
│ 팀별 건강도:  1팀 10  2팀 10  3팀 8 (A: △)  4팀 10          │
│               [다른 길 보기 O]  [다음 →]                    │
└──────────────────────────────────────────────────────────┘
```
- 결과 기호는 모양+색+글자(✓ 해결 / △ 악화 / ✕ 되돌릴 수 없음).
- 팀 점수는 **각 팀이 고른 선택지의 결과**로 계산한다(docs/05 §4).

## S16 다른 길 보기
- 같은 결정의 세 선택지 결과를 나란히 카드로 공개. ✕ 카드는 점선 테두리.

## S17 시간 빨리 감기 (지연 결과)
- 반 경로 결과나 어떤 팀의 결과에 `delayed`가 있으면 표시.
- 연출: 달력·시계가 빠르게 넘어가는 애니메이션(1.5초) → "50년 뒤 …" 문구 → 추가 감점 반영.
- `retry: true`이면 반 경로에 한해 "다시 고르기" 버튼(사건당 1회).

## S18 실제 역사 공개
```
┌──────────────────────────────────────────────────────────┐
│ 실제로는 이렇게 됐어요                                     │
│ 1911 ─ 1937 ─ 1980 ─ 1984~86   (타임라인)                 │
│ · 1980년 정밀 조사: 철 뼈대가 구리와 맞닿은 곳마다 녹슬었어요. │
│ · 약 1,800개의 철 뼈대를 녹슬지 않는 금속으로 바꾸고 …         │
│ 출처: 미국 국립공원관리청(NPS) 외  [교사 패널에서 링크]       │
└──────────────────────────────────────────────────────────┘
```
- `history.lines`를 타임라인으로. 출처는 화면 하단에 짧게, 전체 URL은 교사 패널.
- 역사 합류(historyJoin) 노드는 사건 중간에 같은 디자인의 작은 카드로 나온다.

## S19 사건 정리
- 이번 사건에서 획득한 원칙 카드 + 정리 질문(`wrap.question`) + 팀별 건강도.
- W2 기록 시간 30초 안내.

## S20 알고리즘 매트릭스 (겹쳐 보기)
```
┌──────────────────────────────────────────────────────────┐
│ 다섯 사건, 우리 반의 선택                                    │
│             조사·기록  원인  되돌릴 수  필요한   증거       │
│                                   있게    만큼만            │
│ 1 여신상       ·        ✓              ✓                   │
│ 2 꽃병         ✓                 ✓                         │
│ 3 가면         △                 ✓ ✓                       │
│ 4 단청         ✓        ✓                                  │
│ 5 석탑                           △                ✓         │
│ ─────────────────────────────────────────────────────── │
│ 접착 전문가가 불려 간 사건: 1 2 3 4 5                        │
│ [열 강조: 되돌릴 수 있게]  [팀별로 보기 1 2 3 4]              │
└──────────────────────────────────────────────────────────┘
```
- 행 = 사건, 열 = 원칙 단계, 칸 = 그 단계 태그가 붙은 결정에서 반이 얻은 결과 기호.
- 열 클릭 → 해당 열 강조 + 그 결정들의 선택지 다시 보기.
- '팀별로 보기' → 반 경로 대신 팀 투표 결과로 칸을 채운다.
- 그래프 보기 토글: 사건별 선택 그래프(노드-링크)를 나란히(작게) 보여 "재질은 달라도 문제의 흐름이 같은 모양"임을 보여준다.

## S21 알고리즘 도출
- 큰 빈칸 5개(순서 있는 카드). 학생 발화를 듣고 교사가 카드 순서·문구를 정리(드래그 + 타이핑). 입력은 `algorithmNotes`에 저장.
- [정답 비교] 버튼 → 원칙 5가지(P1~P5) 카드가 옆에 나타나 비교. "우리 반 알고리즘"과 다르면 다른 대로 존중(차이를 토의).
- 마지막 질문: "왜 모든 사건에 접착 전문가가 필요했을까?" → '되돌릴 수 있게'가 모든 사건을 꿰는 원칙임을 정리.

## S23 전이: 내 문화유산 보존 계획

- 예시 1개(`transfer.example`)를 먼저 보여준다. 10분 타이머.
- (P2) 팀 기기에서 미니 선택 그래프를 만드는 편집기(`?mode=team`).

## S24 성찰

## S25 마무리·내보내기

- [CSV 내보내기] [JSON 내보내기] [새 수업 준비(초기화)] — 초기화는 앱 내 모달로 두 번 확인.

## T 교사 패널 (오버레이)
- 현재 화면의 발문, 예상 오개념, 교사 노트, 출처 URL, 타이머 조정, 팀 투표 수정, 선택적 결정 건너뛰기, 실습 건너뛰기(증거 카드로), AI 답변 붙여넣기, 로그 미리보기.
- 학생에게 보이면 안 되는 내용(정답 해설)은 패널에만 둔다.

## M01 전문가 매뉴얼 (manual 모드)
- 세로 스크롤 한 화면. 구성: 나는 누구? / 단서 → 원인 / 꼭 기억할 원리 / 도구 상자(되돌릴 수 있음 ○△✕) / 불려 가는 사건 / 본 팀에 설명할 3문장 연습.
- 글자 크기 20px 이상(휴대 기기 기준), 이미지 최소.

## M02 미니 퀴즈 (manual 모드)
